Case study · Cybersecurity diploma (BTS) · Blue team

Defending a public agency and proving the attack is seen

Protect the servers of a fictional tax administration, then show that a real attack is detected and stopped automatically.

Context
Graded practical work, Cybersecurity BTS
Role
Full implementation, step by step
Deliverable
Technical report with screenshots
9steps validated one by one
3defence layers: network, system, monitoring
1simulated attack, detected and banned

The need

A public agency exposes sensitive servers. The task was to shrink the attack surface to the bare minimum, harden the Linux servers and set up monitoring able to spot an intrusion.

Architecture

pfSense filters traffic in and out. The server runs Wazuh, which collects logs from the agent installed on the client.

What I did

  1. Restrict outbound traffic

    pfSense LAN-to-WAN rule limited to HTTP, HTTPS and DNS. The old allow-all rule is disabled.

  2. Close SSH from outside

    Explicit block of port 22 from the WAN to the server.

  3. Open a controlled admin door

    NAT port forward from WAN port 2222 to the server's SSH for controlled administration.

  4. Harden SSH

    Key-based authentication, PermitRootLogin no, PasswordAuthentication no, AllowUsers.

  5. Enable the host firewall

    UFW with default deny inbound, SSH and 443 limited to the LAN, rate limiting on SSH.

  6. Reduce the system surface

    Fail2ban, account clean-up, password policy, restricted sudo, unused services disabled.

  7. Monitor with Wazuh

    Wazuh server installed with an agent on the client, then a simulated SSH brute-force attack.

  8. Check everything

    Full review of every rule and service after the changes.

  9. Document

    Professional report with screenshots of each step.

Problem solved on the way

The DMZ stayed unreachable

Despite the added rules, the client could reach neither the DMZ nor the pfSense interface. Rather than stall the whole lab, I moved both machines to the LAN to keep going and logged DMZ segmentation as an improvement.

Results

  • The SSH brute force shows up in the Wazuh dashboard.
  • The attacker's address is banned automatically by Fail2ban.
  • Only HTTP, HTTPS and DNS leave the LAN.
  • SSH is no longer reachable directly from the Internet.

Tools

pfSense, Suricata, Snort, Wazuh, Ubuntu Server, UFW, Fail2ban, OpenSSH, VirtualBox
